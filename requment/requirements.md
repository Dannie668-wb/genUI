# 项目需求文档

> 参考：千问"帮我点奶茶" AI Agent 功能复刻

---

## 一、项目概述

构建一个以 **AI Agent 为核心**的智能点餐系统，实现从自然语言指令到完整交易闭环的全链路自动化。核心价值在于"意图理解 → 决策执行 → 交易闭环"的无缝衔接。

---

## 二、功能需求

### 2.1 自然语言点单

- 支持用户用口语化表达下单（如"帮我点两杯冰美式，一杯加糖一杯不加"）
- 从自然语言中提取：商品名、数量、规格属性（冰度/糖度）、配送地址
- 支持复杂组合指令（同一订单多个商品、不同规格）

### 2.2 商家与商品匹配

- 获取用户授权的位置信息
- 调用外部商家列表 API，根据距离、评分、用户偏好智能推荐店铺
- 自动匹配商品并展示供用户确认

### 2.3 生成式 UI（Generative UI）

- 对话过程中动态生成卡片式确认界面，而非硬编码固定页面
- 后端 Agent 将商品数据转化为 UI Schema（JSON）
- 前端渲染引擎将 Schema 映射为可交互组件（按钮、计数器、图片等）
- 支持：商品列表展示、数量调整（+/-）、地址修改、支付确认

### 2.4 工具调用（Tool Use / Function Calling）

- Agent 根据意图自动选择并调用工具，无需用户手动操作
- 核心工具：
  - `search_nearby_shops` — 搜索附近商家
  - `get_menu` — 获取店铺菜单
  - `create_order` — 创建订单
  - `call_payment` — 发起支付
- 可扩展到更多生活服务（地图导航、电话预订等）

### 2.5 记忆与个性化

- **短期记忆**：保存当前会话上下文（最近 N 轮对话）
- **长期记忆**：持久化用户偏好（默认地址、常点品牌、口味偏好如"少冰"）
- 每次会话开始时将用户画像注入 System Prompt，实现"越用越懂你"

### 2.6 支付闭环

- 在应用内直接发起支付，无需跳转第三方 App
- 支持生物识别验证（Face ID / 指纹）
- 支付完成后回调更新订单状态

### 2.7 高并发保障（智商熔断）

- 实时监控系统负载（QPS、CPU、GPU 使用率）
- 超高负载时对特定关键词请求进行降级处理
- 降级策略：直接返回静态安抚文案，不调用 LLM 和业务 API
- 熔断关键词列表支持动态配置（配置中心管理）

---

## 三、非功能需求

| 类别 | 要求 |
|------|------|
| 高并发 | 峰值 QPS 支撑目标（MVP 阶段：100 QPS；生产阶段：50万+ QPS） |
| 可用性 | 熔断降级保证核心服务不崩溃 |
| 可扩展性 | 工具（Tools）插件化，便于接入新的第三方服务 |
| 响应时延 | 正常场景下 Agent 响应 ≤ 5s |
| 隐私合规 | 用户位置、支付信息需授权获取，不明文存储敏感数据 |

---

## 四、MVP 开发路线

| 阶段 | 目标 |
|------|------|
| Step 1 | 跑通 API 调用：大模型解析自然语言 → 输出结构化 JSON → 模拟调用订单 API |
| Step 2 | 引入 Function Calling：用 LangChain 定义工具，模型自动决策调用 |
| Step 3 | 前端交互闭环：聊天界面 + 确认卡片渲染 + 支付 Mock |
| Step 4 | 加入记忆：Redis 存储用户偏好，注入 System Prompt |
| Step 5 | 压力测试与熔断：JMeter 压测 + 简单计数器熔断保护 |
